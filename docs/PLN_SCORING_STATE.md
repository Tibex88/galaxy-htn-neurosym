# PLN Method Scoring — Current State & Limitations

This document describes exactly how PLN ranks HTN method alternatives today,
what drives score differences, and where selection is arbitrary due to
uninformative mock STV values. It is intended as a reference before real
STVs are computed from Neo4j usage frequency.

---

## Background: How Scoring Works

Each Galaxy tool has a **Subjective Truth Value** (STV) in `metta/domain/tool_atoms.metta`:

```
(= (tool-quality fastp) (STV 0.70 0.30))
```

`(STV strength confidence)` where both ∈ [0,1].

The PLN **expectation** of a single tool is:

```
E = confidence × (strength − 0.5) + 0.5
```

A method's **compound score** is the geometric mean of per-tool expectations:

```
score = exp( Σ log(max(Eᵢ, 0.001)) / N )
```

Code: `src/pln/reasoner.py::score_method()` and `get_methods_for_task_scored()`.

---

## Current STV Values (Mock Priors)

All STV values are generated by `src/extraction/metta_generator.py` at extraction
time with the same rule:

```python
strength = 0.7 if tool_has_data_outputs else 0.5
confidence = 0.3   # always
```

### Distribution across the full tool catalog (4,299 tools)

```

STV (0.50, 0.30) — tool has no outputs:       533 tools  (12.4%)

```

> These are the ONLY two STV values currently in the KB.
> `compute_real_stvs.py` is the intended path to replace them with
> Neo4j-derived usage frequency priors.

## Why Some Methods Score Lower

Methods score below `0.5600` only when they contain tools with
`strength = 0.50` (tools that have no data output ports):

```python
# Per-tool expectation breakdown
# STV (0.70, 0.30): E = 0.30 × (0.70 − 0.5) + 0.5 = 0.5600
# STV (0.50, 0.30): E = 0.30 × (0.50 − 0.5) + 0.5 = 0.5000
```

### Query: Show tool-level breakdown for a method

```python
import math
tools = r.get_tools_for_method("COVID_19__variation_analysis_on_WGS_SE_data")
for t in tools:
    s, c = r.get_tool_stv(t)
```

## Selection Is Stable but Arbitrary for Tied Methods

MeTTa's atomspace returns atoms in **insertion order** (the order they were
loaded from `method_sets.metta`). This order is stable across runs but
reflects the alphabetical workflow listing returned by Neo4j, not method quality.

### Query: Confirm stable order across runs

```python
for run in range(3):
    atoms = r._q('!(match &self (= (method-for Assembly $m) $body) $m)')
    names = [str(a).strip() for a in atoms if str(a).strip()]
    print(f'Run {run+1}: {names}')
```

## Decision Tree: What Actually Drives Selection

```
PLN method selection
│
├─ All tools in method have STV (0.70, 0.30)?
│   ├─ YES  →  score = 0.5600  (identical for ALL such methods)
│   │          → winner = FIRST method in MeTTa atom order (insertion/alphabetical)
│   │          → ARBITRARY SELECTION
│   │
│   └─ NO   →  some tools have STV (0.50, 0.30) (no data outputs)
│              → score < 0.5600
│              → lower-scoring method loses to higher-scoring one
│              → WEAKLY MEANINGFUL SELECTION
│
└─ After compute_real_stvs.py (future state):
   → each tool gets frequency-based (strength, confidence)
   → score = genuine signal about KB evidence
   → MEANINGFUL SELECTION
```

## Score Sensitivity to STV Values

The table below shows how score changes as a function of the fraction
of tools with `strength = 0.50` vs `0.70` (N=10 tools, confidence=0.30):

```
Fraction of tools   Score
with s=0.50
──────────────────  ──────
0 / 10              0.5600   (current state for most methods)
1 / 10              0.5539
2 / 10              0.5476
3 / 10              0.5412
5 / 10              0.5281
8 / 10              0.5090
10 / 10             0.5000   (16S_biodiversity_BIOM)
```

With only two possible STV values, the score encodes only one bit of
information per tool: "has data outputs" vs "does not". This produces
a very narrow score range (0.5000–0.5600) with low discriminating power.

---

## What Needs to Change

Run `scripts/compute_real_stvs.py` to replace mock priors with
Neo4j-derived values:

```bash
python scripts/compute_real_stvs.py
```

This computes per-tool:
- **strength** — usage rank percentile across 687 workflows (range 0.3–0.9)
- **confidence** — log-scaled usage count (saturates toward 1.0)

After this, `fastp` (high-frequency, well-tested) will outscore
`Phyloseq_Abundance_plot` (rare, niche) and the ranking will reflect
actual corpus evidence rather than output-port presence.
